# Changelog

## Unreleased

## 0.1.0rc1

- An Agent Client Protocol prompt starts a run that may use only the MCP servers its session selected. A session with no servers now gets none of the locked tools, where before its run was offered every tool the lock granted its stage. Runs started from the command line are unchanged. The run records its selection, and a run stored before this loads with no selection, as before. Starting each server in a sandbox and asking for approval first are a later change.
- An Agent Client Protocol session may select MCP servers in session/new, but only by name: each name must be a server the operator's lock already has, so a client cannot start a command or contact a URL the operator has not locked. The selection is stored with the session (migration 0003) and restored by session/load. Connecting the selected servers to the run, with their sandbox and an approval, is a later change. Compatible: a session with no servers is unchanged.
- The ACX export no longer assumes Amazon's Virtual Voice, which is available only after the author applies for access inside ACX. For each part of the book (the opening credits, each chapter, the closing credits and the retail sample), the `audiobook` stage now writes an audio file as well as the text, read by the narrator named in `EI_NARRATOR`, gated and levelled as the other-store audiobook is. The text stays as the script for Virtual Voice, and the manifest records ACX's rule that unauthorized text-to-speech is prohibited, so the author checks the terms before uploading any audio. Compatible: new output files under `acx/audio/`, two new non-blocking issue codes (`ACX_AUDIO_REJECTED`, `ACX_AUDIO_FAILED`), and the manifest's `narrator` field is replaced by `virtual_voice`, `acx_policy` and `audio` records.
- The screenplay anchors prompt is version 5. Its All Is Lost section now begins with the words "What is lost is" and says why with "because", so a local model writes the wording the format check asks for. Tested on three runs of the Book One logs at about 120,000 characters: all three passed. Compatible: no command, stage or error code changed.
- The local model's window is now 131,072 tokens, and the screenplay anchors prompt is version 4. Version 4 names the seven anchor sections and states the All Is Lost rule, with an example, so a local model writes what the format check asks for. A request the model's window cannot hold is now refused before it is sent, with `CONTEXT_TOO_LARGE`, and says how large the prompt is. Before, an oversized prompt was cut in the middle by the server without a word. The estimate uses three characters to a token, the project's fitting constant, so it refuses a little early rather than sending a prompt that does not fit. Compatible: no command or stage changed; the local server must be started with `OLLAMA_CONTEXT_LENGTH=131072` and `OLLAMA_NUM_PARALLEL=1` to offer the full window.
- An Argo CD Application (`deploy/argocd/application.yaml`) syncs the dev overlay from `develop` into `ei-dev`, with pruning and self-heal, so git is the source of truth. Its namespace carries the label the Kyverno policies match. Argo CD is installed separately (chart 10.19.1) and is verified on minikube: the Application syncs, and the namespace is labelled. Compatible: a new file and a docs section; nothing in the running service changes.
- An optional audiobook phase after the build, off by default. For Audible, the `audiobook` stage writes each chapter as plain speakable text for Amazon's Virtual Voice inside ACX, with opening and closing credits and a retail sample drafted alongside, and a manifest naming that narrator; the pipeline generates no Audible audio. For other stores, the `narration` stage reads chapters with a narrator named by `EI_NARRATOR`, gates and levels the audio, and adds an AI-narration disclosure to its manifest; no engine is built into this release, so naming one is refused with `NARRATOR_UNAVAILABLE`. Compatible: two optional stages, two output folders, one configuration variable, and new issue codes (`ACX_EMPTY_CHAPTER`, `NARRATION_REJECTED`, `NARRATION_FAILED`); no existing code or contract changes.
- An audiobook can now be made from a finished manuscript. `ei book create --kind nonfiction --mode audiobook --source DIR` takes one chapter per file in DIR, in name order, builds the outline from the chapters themselves (their first heading is the title, their first sentence the purpose, each paragraph's first sentence a beat, with no model call), and narrates each chapter with the narrator `EI_NARRATOR` names. Without a narrator the run completes with the manifest marked not narrated. The cost estimate printed before the run is still the whole book's plan, not the audiobook's. Compatible: `--mode` is new and defaults to `book`, which is unchanged; the new error code `RUN_MODE_UNKNOWN` is additive.
- Fixed: a screenplay run's `audit` stage was sent to the nonfiction manuscript auditor, because the audit stage was routed by name and not by kind, so the screenplay's model audit never ran and the run stopped with a message about a nonfiction book config. The nonfiction auditor is now chosen by kind, and any other kind falls back to the stage's default executor. Compatible: nonfiction runs are unchanged; a kind with no executor is still refused with `STAGE_KIND_UNSUPPORTED`.
- The package version goes back to `0.1.0`, and the classifier to Alpha. The 1.0.0 release is not final until its tests have been run thoroughly, so the package says what it is. Compatible: the REST version in the OpenAPI document changes to match; no behaviour changes.
- Groundwork for a screenplay's bible: a bible folder of TOML cards (ADR 0018) is read and checked as a whole before a run uses it. Each subfolder is a kind and each Markdown file a card, whose front matter sits between `+++` lines. `bible.toml` may name the keys each kind requires. The check refuses a duplicate id, a `[[kind: id]]` link to no card, and a real person (`real = true`) with no clearance or with a likeness or voice. Nothing reads the bible into a run yet; that follows with `--bible`. Compatible: no existing behaviour changes.
- A screenplay run takes its bible with `--bible DIR` (ADR 0018). The bible is checked before the run starts and its cards are kept in the run, and each scene is handed the cards it names, by name or id, so a scene's prompt grows by those cards only. A bible given to any other kind of book is refused. Compatible: runs without `--bible` are unchanged.
- Screenplay runs can run the author's own canon check. Set `EI_SCREENPLAY_CANON_CHECK` to the command and `EI_SCREENPLAY_CANON_FOLDER` to the folder it runs in; the command runs there with no shell, and this repository never holds the author's canon. A new `check_canon` stage reads each line that reads `ERROR where: [rule] message` or `WARN where: [rule] message` and records it as a `canon-finding` quality issue. Set `EI_SCREENPLAY_CANON_BLOCKING` to `1`, `true` or `yes` to stop the run at an ERROR; WARN findings never block. A check that exits without status 0 and prints no readable finding stops the stage. With no command set, the stage does nothing. Compatible: the screenplay plan has one more stage after `log_revisions`, the cost estimate treats it as having no model call, and the new issue code `canon-finding` is additive.
- A screenplay run can now start from an earlier run's shooting script lock. `ei book create --kind screenplay --previous-lock FILE` reads the earlier run's `shooting_lock.json` and keeps it in the new run as `previous_shooting_lock.json`, and the lock stage plans from it, so every scene keeps its number. A lock given to another kind of run, or to a build that cannot keep run files, is refused before anything is saved. Compatible: the command tree gains one optional flag, `--previous-lock`, and no existing command, code or stage changed.
- CI now runs the Helm chart's lint and kubeconform validation (defaults and every optional object on), validates each Kustomize overlay, and scans the image with Trivy, failing on fixable HIGH and CRITICAL findings. The worker image also installs poppler-utils in CI, so the book-build tests run instead of skipping. The image applies Debian security updates and no longer ships the base image's pip and setuptools, which the scanner flagged. Compatible: no change to the running service.
- CI runs faster on the same gates. A new push to a pull request cancels the run it supersedes. A change that touches only docs, READMEs or changelog fragments skips the build, toolchain, image, compose, integration and distribution jobs; the unit suite (which holds the docs tests) and the repository gates still run. The uv cache is restored in every job, and the image is built with BuildKit's GitHub Actions cache and reuses the uv download cache. Compatible: no change to the code or the gates.
- The docs now match the code on claim checking (the fact_check stage, ADR 0013), novel editing passes (three), webhooks (sent to configured receivers, with no event for a failed run), and the optional objects in the Helm chart. ADRs 0008, 0010 and 0011 are accepted, and 0012 and 0013 use the same Status line as the rest. The screenplay rehearsal's docstring now matches its plan. Documentation only.
- A non-fiction book's factual claims are checked after copy editing: each claim is searched and its pages read in code, and a claim is kept as written only when a page quotes support for it word for word. Claims no page supports are softened or removed and listed in the quality report; claims that could not be checked are listed and left as written. Compatible: a new stage and three new prompt templates; no existing code or contract changes.
- Long books fit their drafting prompts: the context is fitted with a character estimate instead of the local model's byte count, each section sees the chapter titles rather than the whole outline, summaries may run to 1,000 tokens, and the model request timeout is 30 minutes.
- Groundwork for automated screenplays: the pure Fountain core, with no model call and no new run kind yet. The parser reads a script's title page, its elements and its scenes (scene headings with their `[[key: value]]` notes). The format check applies prompt 09's mechanical test: FADE IN: and FADE OUT. then THE END, allowed times of day, no camera directions except INSERT, no digits in dialogue, parentheticals that lead into dialogue and stay under a tenth of speeches, and no year in a heading in place of (FLASHBACK). Interior thought in action is reported as a note. A Courier page estimate and a Fountain answer screen (refusals are read from action, not dialogue) build on the parser. Compatible: no existing behaviour changes.
- A Fountain title page is read whatever key comes first. Before, a `Credit:` line above the `Title:` line hid the whole title page, so a screenplay could lose its title and credits. Now the title page is the first paragraph that has a Title key, in any order. Compatible: a script that already began with `Title:` reads exactly as before, and no code, issue or stage changed.
- `ei book create` keeps the computer awake for the length of the run: `caffeinate` on macOS and `systemd-inhibit` on Linux, released however the run ends. `--no-keep-awake` turns it off, and a machine without either tool gets a warning. Compatible: one optional flag is added to `book create`.
- The Helm chart can scale the API on CPU with a HorizontalPodAutoscaler (`autoscaling.api.enabled`) and the worker on its RabbitMQ queue depth with KEDA (`autoscaling.keda.enabled`, which needs KEDA installed in the cluster). Both are off by default, so an install without them is unchanged. `docs/DEPLOYMENT.md` gives the options.
- A Helm chart in `deploy/helm/engineering-influence/` runs the API, the worker and the schema migration on Kubernetes, against a Postgres and a RabbitMQ the cluster provides. The pods run as non-root with a read-only root filesystem, and the API token is not mounted. Its install steps and the Secret it reads are in `docs/DEPLOYMENT.md`. Compatible: nothing changes for a run started with `ei` outside Kubernetes.
- Kustomize overlays in `deploy/kustomize/` apply the same Kubernetes objects as the Helm chart without Helm: a base generated from the chart's defaults, and `dev` and `prod` overlays that set the namespace, replicas and image tag. A test fails if the base drifts from the chart. Compatible: nothing changes for Helm installs.
- The Helm chart can run a single-replica SeaweedFS in the namespace (`seaweedfs.enabled=true`) and keep run files in its bucket (`artifactStore.kind=s3`), or point the API and worker at an external S3-compatible service. The default is still the database. The credentials are read from the same Secret the other keys come from. `docs/DEPLOYMENT.md` gives the options and the limits.
- Kyverno admission policies (`deploy/kyverno/policies.yaml`) refuse pods in namespaces labelled `policy.ei/restricted=true` that run as root or are privileged, and report containers without a memory limit. The minikube install labels its namespace and applies the policies when Kyverno is installed. Compatible: nothing applies to a namespace without the label.
- The Helm chart can collect this namespace's pod logs: Alloy reads them through the Kubernetes API and sends them to Loki (`logs.enabled`), and Grafana gets a Loki datasource. Loki accepts connections only from Alloy and Grafana. Off by default; the minikube install turns it on, and `docs/MINIKUBE.md` shows how to query the logs. Tracing is not included.
- A locked MCP server that runs on this machine now runs inside a native sandbox. It has no network, writes only in its own working directory, and cannot read the home directory except the directories its own interpreter and files live in. On macOS the sandbox is `sandbox-exec`; on Linux it is bubblewrap, which also gives the server empty `/run` and `/tmp` directories and fresh IPC, UTS and process namespaces, with no capabilities. Where neither is available, a locked server is refused with `SANDBOX_UNAVAILABLE` and is not started. The approval a session asks for before a server first starts is a later change.
- An agent session asks its person before a selected MCP server first starts. The prompt sends `session/request_permission` for each selected server the session has not yet approved, showing its name, command and tools; an allow is kept with the session, a deny ends the prompt as a refusal and starts no run. Worker boot now verifies each locked server's files without starting any server, and a server starts on the first stage that needs it, once. A server whose tools changed is refused when that stage starts it, not at boot. Migration 0004 adds the approved servers to each session.
- The metrics key is scoped to `/metrics`: the API reads it as `EI_METRICS_API_KEYS`, accepts it on `/metrics` only, and refuses it on every other route. Without `EI_METRICS_API_KEYS`, `/metrics` keeps the main key as before. The Helm chart keeps Prometheus reachable only from Grafana. Found by an automated security review of the observability PR.
- The whole stack runs on a local minikube cluster: an optional in-cluster Postgres and RabbitMQ in the Helm chart, a
`deploy/minikube/up.sh` and `down.sh`, and `docs/MINIKUBE.md` with the steps and the traps. The image now includes the `s3`
extra, so the S3 artifact store works from the container. Compatible: both in-cluster services are off by default.
- The audiobook now has a built-in narrator. Set `EI_NARRATOR=kokoro` on an Apple Silicon Mac with the new `audio` extra (`mlx-audio` and `misaki`), and the narration stage reads each chapter with Kokoro-82M, in the voice `EI_NARRATOR_VOICE` names (default `af_heart`). The engine runs as its own process, so the library is never imported into this code. A segment the engine cannot narrate stops the stage with `NARRATION_FAILED`. Any other narrator name is still refused. The listening test ADR 0014 asked for has not been run; the maintainer chose to ship the engine first. Compatible: the new extra is optional, the new error code is additive, and no existing stage or command changed.
- A novel is drafted one beat at a time and then edited in three passes: story, lines and copy, each in its own voice and bound to the story bible, with dashes kept. The book is built from the last pass, and continuity is checked again on the edited text. Compatible: new prompt templates and a new prompt version for the novel's context pack; no error codes change.
- The locked scene numbers now print. When the lock stage has stored a shooting script, the PDF and the EPUB use it: the PDF puts each scene's number at the right margin of its heading, and the EPUB floats it to the right. Without a locked script, both outputs are built as before. Compatible: no command, code or stage changed; the PDF and EPUB are the same except for the numbers.
- The Helm chart can run Prometheus, scraping the API's `/metrics` with a dedicated metrics key, and Grafana with its Prometheus datasource provisioned (`observability.enabled`). Off by default. The minikube install turns it on, and `docs/MINIKUBE.md` gives the steps to open both. Compatible: nothing changes for an install without it. Logs and tracing are not collected yet.
- Secrets can come from OpenBao, an open-source Vault fork, through the External Secrets Operator (`openbao.enabled`): the chart runs a dev-mode OpenBao for a local cluster, a SecretStore, and an ExternalSecret that copies the app's values into the Secret it already reads. Off by default. The minikube install uses it; the operator is a cluster-wide prerequisite, and production runs its own OpenBao.
- Traces are exported to Tempo when `EI_OTLP_ENDPOINT` is set. The API records a span for each request (FastAPI instrumentation), and each run phase records a `run_phase` span with its artifact type, from the API and the worker alike. The Helm chart runs Tempo behind `tracing.enabled=true` and points both pods at it, and Grafana gets a Tempo data source. With the setting empty, which is the default, nothing is exported and nothing changes. Compatible: one new setting, one new chart value and the `tracing.*` block; no existing behaviour changes.
- A book's outline is sized to its length: one chapter per 3,500 words of the target (3 to 30), stated to the model and refused
when it is more than 15% away, with the new `OUTLINE_CHAPTER_COUNT` error. Outlines may run to 8,192 tokens, and a chapter is at
most 6,000 words. Compatible: one error code is added, and the prompt versions `stage_outline` 5 and `novel_outline` 2 are new.
- Webhooks now send pipeline.failed when a run stops for a reason it cannot recover from (stage-failed or retries-exhausted), or overspends its budget (budget-exceeded). The event carries the code, the project and the stage, never the error text. It is an addition to the v1 catalogue, so existing receivers, which ignore unknown types, keep working; the contract snapshot records it. Compatible: no existing event or payload key changes.
- A draft that a model declines to write is asked again once in other words, and a second refusal stops the stage with `DRAFT_REFUSED` naming the chapter and section. A section well under its length is asked again for the full length; one that stays short is kept and reported as `DRAFT_SHORT`. Compatible: one error code is added, and the report gains a non-blocking issue code.
- A revision script's printed pages carry a running header with the revision and its date, for example Revision: Pink (2026-11-27), on every page after the title page. The title page has none, and an ordinary script prints as before. The header is read from the title page's Revision line, so no new input is needed; the PDF was compiled with LuaLaTeX to check it. Compatible: scripts without a Revision line are unchanged.
- A screenplay run now has two revision passes after the scene revision. A structure pass (`structure_scenes`, prompt `screenplay_pass_structure`) makes each scene's card happen on screen and turn toward its next beat. A dialogue pass (`dialogue_scenes`, prompt `screenplay_pass_dialogue`) cuts lines that explain what the audience can see and keeps the lines that carry the plot. Each pass keeps the model's answer only when it passes the same section check and length rule as the revision; otherwise the scene carries forward unchanged, and when the money runs out the rest carry forward. The assembled script reads the dialogue pass's output. The format pass is the existing Fountain format check on the assembled script, so it is unchanged. Compatible: the two stages and their prompts are new, and no command, error code or issue code changed.
- Screenplay runs now write two reports after the scene numbers are locked. A new `log_revisions` stage reads each scene's draft and revision, and writes `revision_log.md`, a table of every locked scene with its status (`revised` or `draft kept`) and its word counts, and `source_mapping.md`, a table of each scene's card, beat and cited source files. Omitted scenes stay in both tables with their numbers. Not included: the coloured revision pages with `*` marks and dated headers, which need a previous printed version to compare against. Compatible: the screenplay plan has one more stage after `lock_script`, the cost estimate treats it as having no model call, and no issue codes or error codes changed.
- The API and the worker can keep a run's files in an S3-compatible bucket instead of Postgres: set `EI_ARTIFACT_STORE=s3`, `EI_S3_BUCKET`, and the credentials `EI_S3_ACCESS_KEY_ID` and `EI_S3_SECRET_ACCESS_KEY`; `EI_S3_ENDPOINT_URL` points it at SeaweedFS or another S3-compatible service. Files are write-once as they are in the database. The `s3` extra provides boto3. The default stays `database`, so an existing deployment is unchanged. The command-line book commands, the MCP server and the local runs still read the database; `docs/CONFIGURATION.md` says so.
- The mechanical checks for a screenplay's architecture (prompt 08) are in place, ahead of the model stages that write it. The anchors check requires the seven sections, a one-sentence dramatic spine, opening and closing images with no thought or V.O., All Is Lost stating what is lost and why, and a named structural mode. The beat-sheet check requires the fifteen beats in order, page ranges that move forward within the film, a relationship function from the fixed set, and All Is Lost about three-quarters through. Compatible: new checks only; no existing behaviour changes.
- Screenplay runs have their architecture stages: a brief, the anchors, the beat sheet and the scene cards. Each is one prompt (four new templates, `screenplay_*`), and each answer is checked by the mechanical checks before it is stored, so a beat sheet missing a beat stops the run where it was written. A screenplay run still cannot start: its brief is refused until the drafting stages land. Compatible: four new prompt templates, a new stage plan and executor for the screenplay kind, and no change to the other kinds.
- A screenplay run now audits its source before it plans the film, and sets the look of the film before it drafts. The new `audit` stage writes a verdict on every source file (in order and numbered from 001), how each major character is internalized, the source each beat comes from, what the film compresses, and what it adds; every addition must be marked FILM. The new `visual_grammar` stage writes the light, colour and texture of each primary set and a visual signature for each major character. Both are checked before they are stored. The anchors and beats stages now read the source files under their numbers rather than the brief's inputs. Compatible: the anchors and beats prompts move to version 2, two new prompts ship, and runs already past the beat stage keep the answers they stored.
- The screenplay format check now refuses a (beat) parenthetical: a pause belongs in the action, and the message says how many a script has. The check is part of the architecture and drafting gates, so a script with them fails at the stage that wrote it. Compatible: scripts without (beat) parentheticals pass as before.
- The assembled screenplay must now place each beat where the beat sheet puts it. Each beat's first scene card must begin within 5% of the film, by the script's estimated Courier length, of its planned place, and every one of the fifteen beats must have a scene card. A script that fails is refused at assembly with `STAGE_OUTPUT_INVALID`, naming each beat that is missing or out of place. Compatible: no existing API or stored artifact changes; a run whose script keeps its beats in place is unaffected.
- Screenplay runs can be created and drafted from their source files. `ei book create --kind screenplay --source DIR` now succeeds: a screenplay run without a source folder is refused with `SCREENPLAY_NO_SOURCES` before anything is spent. The scene-cards stage is given every source file under its number, and each card must name the source numbers it draws on in a `**Sources:**` field. Drafting sends each scene only the sources its card cites, and a card that cites a source the run does not hold stops the stage. The screenplay brief is no longer refused. Compatible: the scene-cards and scene-draft prompts move to version 2 (cards gain the `**Sources:**` field), `SCREENPLAY_NO_SOURCES` is a new user-facing error code, and runs created before this change that have no sources cannot be drafted.
- Screenplay drafting now checks each scene's dialogue against the sources it was written from: a speech that repeats twelve words of a source in a row, ignoring case and punctuation, fails the check, so research is spoken as dialogue rather than read out of a file. Action is not checked. A scene that fails is drafted once more, and if it fails again the stage stops with `STAGE_OUTPUT_INVALID`, as for the other scene checks. Compatible: no new flags, no new artifacts and no change to runs that have not reached drafting.
- A screenplay scene whose first draft is a refusal (a refusal in its action) or fails a check is drafted once more, and the second draft is told the problems, as untrusted evidence, so it corrects them rather than guessing. The drafting stage now uses the Fountain answer screen, which reads a refusal only in the action, so a character who says "I can't" in dialogue is not mistaken for one. Compatible: a scene's first draft is unchanged.
- The drafting stage of a screenplay is in place, ahead of the model adapter that writes each scene. Scenes are drafted in prompt 09's order (the opening and closing images, then All Is Lost, then the rest, with the likely-shared scenes last), each one checked as a single scene under the Fountain format rules, and a scene that fails is drafted once more before the stage stops and names the problems. A scene already stored is kept, so a redelivered stage drafts only what is missing. When every scene is stored, the script is assembled in card order as `screenplay.fountain`. Scene cards that cannot be read are refused as `SCENE_CARDS_UNREADABLE`. Compatible: new services and a new error code; no existing behaviour changes.
- The pure parts of drafting a screenplay are in place. The drafting order follows prompt 09: the opening and closing images and All Is Lost first, the rest in card order, and the likely-shared scenes last. Each drafted scene is checked as one scene under the Fountain format rules. The assembler joins the scenes under their title page into one script, closed with FADE OUT. and THE END, and refuses a title page without a title, an empty screenplay, or a scene that is not exactly one scene. Compatible: new services only; no existing behaviour changes.
- Screenplay runs now produce an EPUB of the script. After rendering, a `build_epub` stage lays the script out as one EPUB 3 page (the title page, then each element with its screenplay indent, in a monospace style) and stores `screenplay.epub`. The archive is checked with epubcheck, and an EPUB it rejects is not stored: the stage stops and names the first findings. Compatible: the screenplay plan has one more stage after `render_script`, the cost estimate treats it as having no model call, and the run's issue codes are unchanged.
- Groundwork for automated screenplays: the `screenplay` book kind exists in the enum, and its source is read from a folder of Markdown and text files (ADR 0017). Each file becomes a numbered, digest-pinned source; an empty or missing folder, a file over 2 MB, and a file with control characters are refused. Screenplay runs are not yet available: `ei book create --kind screenplay` is refused as unsupported until the plan's later pull requests land. Compatible: the new kind value and three error codes (`SOURCE_EMPTY`, `SOURCE_FOLDER_MISSING`, `SOURCE_TOO_LARGE`); no existing kind changes.
- A screenplay's scenes are drafted by the model. The new `screenplay_draft_scene` prompt writes one scene in Fountain from its scene card and the anchors and beat sheet, sent through the same tool loop and spend guard every other stage uses. A retry is a fresh request, so the journal does not replay a failed answer. An incomplete or empty answer stops the stage. The drafting stage checks each scene and assembles the script, so the model's output is checked before it is stored. Compatible: one new prompt template, pinned and listed; the drafter port takes the try number; no existing behaviour changes.
- The rendered screenplay PDF is now checked against the KDP print layout, the same rules a book's interior meets: the gutter for its page count, the quarter inch to the outside, top and bottom edges, and no more than two blank pages in a row. A PDF that breaks them stops the render stage with `STAGE_OUTPUT_INVALID`, naming the pages. Compatible: a film whose PDF already sits within these margins is unaffected; the standard screenplay layout is well inside them.
- The screenplay rehearsal now runs a screenplay plan through every stage that does not need a paid model or the TeX toolchain: the revision log, a clean canon check, and the video stage (which writes a not-generated manifest with no provider). A toolchain-marked test runs the whole plan, render and EPUB included. The live smoke test page says so. Tests and documentation only.
- Screenplay runs now render their assembled script to a PDF. After assembly, a `render_script` stage lays the Fountain out in standard screenplay pages (US Letter, 12 point Courier, the usual indents for character, dialogue, parenthetical and transitions), typesets it with LuaLaTeX, and stores `screenplay.pdf` with a `render.md` giving its page count. A script that does not typeset stops the run with the end of LaTeX's log in the message. A film over the 195-page ceiling stops the run; a film past three hours (180 pages) is recorded as a note and the run finishes. Compatible: the screenplay plan has one more stage after `assemble_script`, the cost estimate treats rendering as having no model call, and no existing run is affected. The run's issue codes gain two new entries, `revision-kept-draft` and `screenplay-length`; adding codes is compatible, and existing codes are unchanged.
- Screenplay runs now revise each drafted scene and then assemble the script. After drafting, a `revise_scenes` stage asks the model once per scene for a tighter revision, and keeps it only if it passes the Fountain scene check and stays within 10 per cent of the draft's length; otherwise the drafted scene is kept, and the report says how many scenes kept their draft. An `assemble_script` stage then joins the revised scenes, in card order, into `screenplay.fountain`, and refuses a scene that is not exactly one scene, or a script that breaks the whole-script format rules. Drafting no longer writes the script. Compatible: the new `screenplay_revise_scene` prompt is version 1, the screenplay plan has two more stages after `draft`, and the cost estimate prices the revision as one call per scene and leaves it out when the money runs out.
- A revised shooting script can now mark its changed scenes with their revision colour. `book create --previous-script FILE --revision N` gives the earlier run's `shooting_script.fountain` as the baseline; revision 1 is Blue, 2 is Pink, and so on through the standard order up to 9.
