Gave the remaining classes their interfaces, so every class in the package now has one: 44 new `…Interface` modules for the adapters in `infrastructure/` (33, including the cover painter toolkit), the transports in `interactions/` (6) and the composition code in `runtime/` (5), built under the same rules as before (methods only, `__slots__ = ()`, type-only imports). A class that already implements a port or another class's interface, such as `ConstantTimeApiKeyVerifier`, the `Traced*` services and the RabbitMQ adapter, keeps that one and gets no second interface.

The SDK package follows the same rules: `EngineeringInfluenceClient` and `AsyncEngineeringInfluenceClient` inherit `EngineeringInfluenceClientInterface` and `AsyncEngineeringInfluenceClientInterface` (in `engineering_influence_sdk.interfaces`), with identical constructors, methods and signatures, and the same `__all__`. The built SDK wheel ships the new package and still installs and imports on its own. A new architecture test holds the SDK to the interface rules and checks that each client's signatures match its interface.

Tidied two things from the previous step. `SqlModelLedger` and `SqlModelOutbox` had been given a redundant second interface on top of the port they already implemented; those two generated modules are gone, and the tables they create are unchanged, statement for statement. `LedgerRepositoryInterface` is a port that extends `LedgerInterface`, so it moved to `engineering_influence.interfaces.ledger_repository_interface`; as with the earlier internal moves there is no alias. The generated REST schema, the MCP tool list and every `ei` help page are byte-identical.

The architecture ratchets for classes without an interface, layer crossings, interface-rule breaks, unpaired interfaces, effectful imports and model purity are all at zero. Only the files and folders held by the deprecation shims remain above zero.
