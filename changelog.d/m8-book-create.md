`ei book create` makes a whole book from an idea, with nobody in the loop: `ei book create --kind nonfiction|novel "<idea>" --budget-usd 5 --out DIR --profile author.toml`. It runs every stage of the plan in one process (no database server, queue or worker), with the models and search the environment names, and writes the book project, the finished PDF, EPUB, covers, listing and manifest, the readiness reports and `quality-report.json` to `DIR`. The run is kept in a SQLite file beside it (`DIR.state/`), so a process that dies loses nothing that was paid for: `--resume` continues it and a model call already made is replayed, not paid for again; a run that asks for more budget stops and writes nothing until `--resume --approve-spend`. The budget has no default, and the author profile is required; both are checked before anything is spent, as is a strict release's need for pricing. The author profile may now carry a `[pricing]` table (`verified_on`, `source_url`, `ebook`, `paperback`, optional `hardcover`) that goes into the book's `[release.pricing]`, so **a run's book passes `--strict-release` with epubcheck required** (`--strict-release` on `ei book create`, or `EI_BUILD_STRICT_RELEASE`); a hardcover price also declares the book a KDP hardcover. That is proven with the real toolchain, for a book and a novel, in `tests/toolchain/test_run_builds_book.py`. A failed run is final, as on a worker, but what it made is still written out. Retries wait 2, 10 then 30 seconds between attempts.
