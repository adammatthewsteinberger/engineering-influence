Skills (ADR 0008, slice 5). A skill is a TOML file of text, with a part for each stage it speaks to, that a person installs to steer a stage's prompt: it adds no tool, no command and no address, and cannot widen what a stage may call. `ei skills add FILE` checks it strictly, records the SHA-256 of its bytes in `ei-skills.lock.toml` and keeps a copy in `skills/` beside the lock; it enables nothing. `ei skills enable NAME STAGE` (at most four per stage), `disable`, `remove`, `list` and `verify` do the rest. A run reads a skill lock only when `EI_SKILL_LOCK` names it, checks every enabled skill against its hash before any tool server is started or any call is made (`SKILL_LOCK_MISMATCH`, `SKILL_LOCK_MISSING`), and adds each stage's skills to the end of its user prompt inside a fixed frame (the new `skill_guidance` template), never the system part. The skills' identity goes into the prompt version, so a resumed run replays an answer only for the same text; a stage with no skill sends exactly what it always did. Text a reviewer cannot see (zero-width and bidirectional marks, control characters, private-use code points) is refused, a part is capped at 8,000 characters and a file at 64 KiB, and a copy of the block's tags inside a skill is defused. A skill is trusted as installed: one that was hostile when locked is followed, which is why it is read before it is enabled. See docs/SKILLS.md.
