Screenplay runs now lock the script's scene numbers. A new `lock_script` stage runs after the script is assembled. It checks that each scene card is one scene of the script, numbers each scene, and stores the numbers as `shooting_lock.json` and the numbered script as `shooting_script.fountain`. A new scene takes the next whole number at the end, or a letter after the scene before it (42A, then 42B). A scene the script drops stays in the lock as omitted, so its number is never reused. A locked scene that has moved refuses the stage. A run can be given the previous lock as `previous_shooting_lock.json`, and the numbers carry over from it; how a previous lock gets into a new run is not part of this change. Compatible: the screenplay plan has one more stage after `assemble_script`, and the cost estimate treats it as having no model call. The error code `SHOOTING_LOCK_UNREADABLE` is new in the public error list; adding a code is compatible, and no existing code changed.
