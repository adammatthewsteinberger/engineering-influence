The release workflow can rehearse the upload on TestPyPI before PyPI, and uploads the core and the SDK from separate jobs and environments (`pypi` and `pypi-sdk`, `testpypi` and `testpypi-sdk`), because a pending trusted publisher is told apart by its environment. The new `testpypi` jobs use trusted publishing and no token, and run only when the repository variable `PUBLISH_TO_TESTPYPI` is `true`. When a rehearsal runs, the `pypi` job waits for it and does not run if it failed or was cancelled; the SDK is uploaded only after the core. None of the four jobs has run.
