Publishing now follows the branch. A merge to `develop` uploads a development build (`<version>.dev<run number>`) to TestPyPI, and a merge to `main` is a release: the guard checks the version and changelog, a GitHub release and the tag `v<version>` are created, and the packages are uploaded to PyPI. The core and the SDK are uploaded by separate jobs from separate environments (`testpypi` and `testpypi-sdk`, `pypi` and `pypi-sdk`), because PyPI tells pending trusted publishers apart by their environment. Each index is off until its repository variable (`PUBLISH_TO_TESTPYPI`, `PUBLISH_TO_PYPI`) is `true`, and each environment's reviewers approve every upload. A tag push no longer starts a release. None of the four upload jobs has run. See ADR 0009.
