The tool loop (ADR 0008, slice 2) is built. `RunToolLoop` runs every model-backed stage: it asks, runs the tools the model calls through `ToolRunner`, and asks again, within limits on turns (8), tool calls (16), result size (20,000 characters) and seconds per call (60). A stage gets only the tools its recipe names; a call to any other name, or with arguments that do not fit the tool's schema, runs nothing and is answered with an error the model can read. Every tool call is journaled by tool and arguments, and `CallModel` now journals a tool turn whole (text and calls, keyed by the tools offered and the conversation so far), so a run that stopped in the middle of a conversation replays what it had finished for nothing and goes on from the first unfinished turn. A request with no tools is keyed and stored exactly as before. A model that calls a tool nobody offered is billed, journaled and refused. No tool is registered yet, so the model still has none; `web_search` and `fetch_url` come next. Not run against a live provider.
