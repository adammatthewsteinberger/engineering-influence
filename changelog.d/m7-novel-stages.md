A novel run now has its first four stages (M7.3): `brief`, `story_bible`, `beats` and `outline`, each one versioned prompt with no tools (`novel_brief`, `novel_story_bible`, `novel_beats`, `novel_outline`). The story bible is one JSON object that the new `StoryBibleParser` reads strictly (the first object in the answer; every text collapsed to one line and stripped of control characters; the timeline sorted) and a bad one stops the run where it was written (`STORY_BIBLE_INVALID`); the outline uses the same chapter format non-fiction does, so one parser reads both. The runtime now dispatches by the brief's kind, so non-fiction is unchanged, and every novel stage first asks `ContentPolicy` whether the model is recorded as allowing the brief's violence and heat level, before any call. The levels are also in the prompts. Drafting and everything after it for a novel is not built, so a novel run ends at the outline, and nothing has run against a real model. See `docs/NOVELS.md`.
