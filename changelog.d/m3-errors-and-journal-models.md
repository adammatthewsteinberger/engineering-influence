Added the first M3 building blocks, all pure and not yet consumed: `BudgetExceededError`, `FailureKind` (transient, capacity, unrecoverable, which decides between retrying, parking a run for credit and stopping), and the journal's `JournalKey` and `JournalEntry`. A key is the model snapshot, parameter hash, prompt version and context hash of a request, and its SHA-256 digest is stable and separator-safe, so a resumed run can find the answer a repeated request already got instead of paying for it again. `Budget` now raises `BudgetExceededError` when a reservation does not fit or a call cost more than it reserved; it is a `ValueError`, so existing handlers keep working.
