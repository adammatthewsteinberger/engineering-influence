The stdio transport and the `ei tools` commands are built (ADR 0008, slice 4b). `ei tools add NAME -- COMMAND` runs an MCP server once and records it in the tool lock (the SHA-256 of its executable and scripts, the name and version it reported, a hash of every tool it advertised); `ei tools list` shows the lock without starting anything; `ei tools verify` runs each locked server and compares it, and never starts one whose files have changed. A server runs as a child process in its own process group with a bare environment (no API key unless the lock names it), a throwaway home directory, and time, memory and disk limits, and is stopped by killing the whole group. Launchers such as `npx`, `uvx` and `docker`, and scripts given by relative path, are refused before anything runs. This is not a sandbox: a server can still read any file the user can and use the network. The client has been run against a small server written for the tests, not third-party servers, and nothing in a run reads the lock yet. See docs/TOOL_LOCK.md.
