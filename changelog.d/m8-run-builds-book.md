A non-fiction run now ends in a built book. A new final stage, `build`, takes the run's own manuscript through the same publish pipeline as `ei book publish` (audit, interior PDF, covers, EPUB with epubcheck, release-readiness) in a scratch folder, packages the KDP bundle, and stores the result in the run: `book/<slug>.pdf`, `.epub`, the covers, `listing.md` and `MANIFEST.json`; `build/` with the readiness reports and tool logs; a deterministic `quality-report.json` (status, errors, warnings, steps, and a size and sha256 for every file); and `build.md`. A failed build stores what it produced before it fails the run (`BUILD_FAILED`). The stage needs the TeX worker image; `examples/docker-compose.tex.yml` switches the compose stack's worker to it, and `docs/WORKER_IMAGE.md` says how. A strict release needs the author's pricing inputs, which a run cannot invent, so it is off by default: set `EI_BUILD_STRICT_RELEASE=1` to fail a run on any readiness warning. Proven with the real toolchain: `tests/toolchain/test_run_builds_book.py` runs the scripted rehearsal of the whole plan and checks the PDF, the EPUB, the report and its checksums. Building the book from a run also exposed a bug in KDP packaging: it expected a hardcover file for every book, whether or not the book had a hardcover, and refused with "missing artifact"; it now reads the book's own format settings.
