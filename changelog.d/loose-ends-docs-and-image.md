The worker image now includes `procps`, which provides `ps`. The slim image did not, so the process runner's memory meter failed there with `FileNotFoundError` on the first tool that ran past one sampling interval, and a TeX or EPUB build could stop mid-run. Built and checked in the slim image: the meter now reads a process group's memory. A missing `ps` is now a clear build error that names the package to install, rather than a crash. The troubleshooting page has a table of the error codes a person is likely to meet, each with its message as the code prints it and what to do, and the remaining codes are named as internal in a test that fails when a new code is added without a decision. A test pins the packages the Dockerfile installs to the packages the worker image page describes, and the CI toolchain's package list to the same set.
