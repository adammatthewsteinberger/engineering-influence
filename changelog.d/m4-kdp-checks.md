Added the KDP listing checks to the release audit. A description now has a maximum of 4,000 characters (`description-too-long`, lowered per book with `release.maximum_description_characters`), and a new `CategoryCheck` validates `release.categories`: up to three Amazon browse paths such as `Books > Literature & Fiction > Mystery`, unique, with at least two levels, refusing a fourth (`too-many-categories`), anything that is not a path (`category-not-a-path`), a duplicate however it is spaced or cased (`duplicate-category`) and a BISAC subject code, which is a different scheme (`category-is-bisac`); errors in a strict release, warnings otherwise. A book with no categories gets the warning `categories-not-declared`, never an error, so existing books keep passing a strict release. The check cannot know Amazon's browse tree, which has no API, so the names are confirmed at upload, and the limits are KDP's published ones as understood today. The back cover now fails fast and clearly when the description cannot fit above the barcode area: the typesetter raises `BackCoverTextTooLongError`, a `BookBuildError`, carrying the description's length, how many characters fit at this trim size (measured with the same layout code, not guessed) and the overflow in inches, instead of drawing text into the barcode area and failing after rendering with a count of stray pixels. With the default style about 3,000 characters fit at 6x9 and 5.5x8.5 and about 2,200 at 5x8, below KDP's 4,000-character listing limit, so a description can pass the audit and still be too long for the cover. New tests prove that text at the limit never touches the barcode area at any trim size, for the paperback and the hardcover, and that ink placed there is always caught.
