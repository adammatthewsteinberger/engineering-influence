The tool lock and the MCP client are built (ADR 0008, slice 4a). A lock file (`version = 1`, TOML) records each approved MCP server: its command, the SHA-256 of its executable and of every script in its arguments, the name and version it reported, the names it is given as environment variables, and a hash of every tool it advertised, so a changed file or a reworded tool description is noticed. Package launchers such as `npx`, `uvx` and `docker` are refused because their code cannot be hashed. `McpClient` speaks `initialize`, `tools/list` and `tools/call`, offers a server nothing (it refuses every request a server sends except `ping`), and treats everything a server sends as untrusted and bounded. `ToolLockVerifier` compares a lock with the files on disk and with what a running server reports. Not wired in yet: nothing starts a server, reads a lock in a run, or offers a server's tools to a stage, there is no `ei tools` command, and the client has only been tested against a fake transport. See docs/TOOL_LOCK.md.
