Tests now pass fakes into the classes that take their collaborators instead of patching production classes, wherever the code already allowed it: the controller and `ei book` tests inject fake LaTeX, EPUB, cover, verifier and renderer collaborators, the publish-step tests inject a fake EPUB verifier, the MCP test overrides `build` in a subclass, and the cover-plugin loader tests pass an entry-point lookup. That took the `monkeypatch.setattr` calls from 33 to 21; what remains are standard-library or test-local patches and nine production targets that the class under test builds itself, which wait for services to receive their helper services. A new architecture test lists those nine with the reason for each, so a new patch of production code fails the build and a removed one has to come off the list.

Three small seams make that possible, all optional and defaulting to the previous behaviour: `CliRuntime(publishing=...)` takes the factory that wires the `ei book` commands, `CoverPluginLoader(discover=...)` takes the entry-point lookup (`CoverPluginLoader()` is unchanged for existing callers, including the public cover API), and `PublishPipelineProvider` takes the EPUB verifiers from `PublishingControllerFactory` rather than building them. The generated REST schema, the MCP tool list, every `ei` help page and the wheel's file list are unchanged.
