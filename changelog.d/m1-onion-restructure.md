The package is now a strict onion, and the rules are enforced by the build. Layers, from the inside: `errors`, `models`, `contracts`, `interfaces`, `services`, then `controllers`, `repositories` and `infrastructure`, then `interactions`, then `runtime`, the only layer that builds concrete classes (`docs/adr/0006-onion-layers-and-interfaces.md`, `docs/ARCHITECTURE.md`). Every folder has an `interfaces/` folder, there is one class per file, and every class implements an interface; `lint-imports` and nine zero-tolerance architecture tests check it, and tests pass fakes instead of patching production code. This summarises the `m1-r*` entries below, which carry the detail.

**Breaking, for code that imports internals:** `domain` is now `models`, `interaction` is `interactions`, every `*Port` is a `*Interface`, and `engineering_influence.publishing` is gone, its classes redistributed across the layers (`scripts/refactor/move_map.toml` maps every old module to its new one). Cover plugins import from `engineering_influence.covers`. The `ei` command, the REST API, the MCP tool, the SDK and the entry-point group `engineering_influence.covers` are unchanged, and the generated OpenAPI document, the MCP tool list, every CLI help page and the fixture book's typeset pages and EPUB members are identical to before the restructure.
