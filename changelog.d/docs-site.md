The documentation is now also built as a website from the same Markdown, so there is one copy to keep true. `scripts/build_docs_site.py` assembles the pages (a clean address for each, links rewritten so a link to another page works between pages and a link to anything else points at that file on GitHub, a page listing the decision records, `llms.txt` and `llms-full.txt` and a `robots.txt` at the root), ProperDocs builds them with warnings as errors so a link or heading that goes nowhere fails the build, and `scripts/inject_docs_meta.py`, adapted from Vibey's, adds each page's description, canonical address and Open Graph and Twitter tags and the home page's `SoftwareApplication` description. The Vibey stylesheet comes from the locked `vibey-engine` package at build time. A new `docs.yml` workflow builds on every pull request that touches the documents and, on `develop`, publishes to GitHub Pages only when the repository variable `PUBLISH_DOCS` is `true` and Pages is switched to GitHub Actions; there is no analytics. Vibey's own `release-surfaces` workflow was not adopted whole because it also pushes the wheel to GHCR on every release run, which would bypass the gating on image publishing. Nothing has been published and the workflow has not yet run on GitHub: the build and the metadata step were run locally and the pages were looked at in a browser.
