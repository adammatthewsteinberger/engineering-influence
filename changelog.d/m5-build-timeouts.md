Every external build tool now has a deadline, and a tool that passes it is stopped together with everything it started. `latexmk` and `tex4ebook` get 30 minutes, `epubcheck` and the page renderer 10; the build then fails with a `BookBuildError` that names the tool and shows its last output, instead of holding a worker for ever. The four tools run through a new `ProcessRunner` (an interface and an implementation, injected like any other collaborator), which starts each tool in its own process group and kills the group, because `subprocess.run(timeout=...)` stops only the direct child and `latexmk` and `tex4ebook` run their work in grandchildren that keep the output pipe open. Ctrl-C now stops the tool and reaps it, too. The deadlines are constructor arguments with these defaults, not settings. Stopping a whole tree needs process groups, so it works on Linux and macOS and not on Windows. A new toolchain test hangs real `latexmk` and real `tex4ebook` with a document that loops forever and checks that nothing is left running, and the fixture books build byte-identically through the new runner (final PDFs, EPUBs, covers and reports; only build timestamps in scratch files differ).
