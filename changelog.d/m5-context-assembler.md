Added `ContextAssembler`, which fits one drafting call's context into an input-token budget. The style and the story bible (or outline) go in the system text, where the adapter can cache them; the beats, the instruction, the newest prior-chapter summaries and the end of the previous chapter go in the prompt. The fixed parts are never cut. Summaries are kept newest first, then the previous chapter's tail takes the room left, cut from its start to a paragraph boundary. It finds the fit by binary search over the model's own `count_tokens`, so a draft needs a few dozen counting calls however long the book is, and it raises `CONTEXT_TOO_LARGE` when the fixed parts alone do not fit.
