Added integration tests that run against a real PostgreSQL and RabbitMQ, a new `integration` CI job, and a state-machine property test. `tests/integration/stack.sh up|env|down` starts both services in Docker with random credentials (`eval "$(sh tests/integration/stack.sh up)"`, then `uv run pytest -m integration tests/integration`); the `integration` marker is deselected by default, the tests skip when the stack is not running, and the CI job sets `EI_REQUIRE_INTEGRATION=1` so a missing stack fails instead of passing with nothing tested. They check that the migrations build exactly what the models describe on PostgreSQL, that threads racing to change a run, record a journal entry or store an artifact leave exactly one winner, that large binary artifacts round-trip, that jobs are consumed, dead-lettered and redelivered through the broker, and that a book run finishes through both services with every artifact byte-identical, spend exactly equal to the journal and nothing dead-lettered, whether a worker dies before storing a change, before queueing the next stage or before acknowledging, and that a run parked for credit resumes through the real broker. A Hypothesis state machine drives random deliveries, duplicate deliveries, failures, resumes and cancels in memory and checks after every step that a finished run never changes, a run never moves backwards, spend equals the journal, artifacts are never rewritten and a run that can still move always has a job queued for its stage. **Fixed:** the baseline migration created timezone-naive timestamp columns on PostgreSQL while the models use `TIMESTAMP WITH TIME ZONE`, which stores an aware UTC value shifted into the session's own zone; SQLite ignores the difference, so only the PostgreSQL test could see it. No release contained migrations, so the baseline was corrected in place: a development database created by `ei db upgrade` before this change should be recreated.
