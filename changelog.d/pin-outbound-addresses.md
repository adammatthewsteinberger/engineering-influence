Outbound connections for `fetch_url` and remote MCP servers are pinned to the address that was checked, closing the DNS-rebinding gap. The new `PublicHttpsUrlPinner` resolves a name once, has the URL policy judge every address it returned, and hands the caller the vetted address together with the name for the `Host` header and for TLS, so the certificate is still checked against the name and not the address. A name that resolves public and then inward is sent to the public address only. Only one address is tried, a request to a name that fails to resolve or fails IDNA encoding is refused, and `fetch_url` sends `Connection: close` so a connection verified for one name is never reused for another that shares its address. Proven over real TLS with a self-signed certificate. Signed webhook delivery still asks the policy and lets the client resolve again, and is unchanged.
