Plugins (ADR 0008, slice 6a). A plugin is one TOML file that bundles skills and tool server definitions, so a person can review and pin them together. `ei plugins show FILE` says what installing it would do; `ei plugins add FILE` locks its skills (each enabled for no stage), keeps a copy of the bundle in `plugins/` and records its SHA-256 in `ei-plugins.lock.toml`; `list`, `verify` and `remove` check and undo it. **Installing starts nothing, contacts nothing, grants nothing and enables nothing:** the `ei tools add` command for each server is printed, shell-quoted, for a person to review and run, because that command is what starts a server. A bundle has no key for a grant or a stage, and any unknown key is refused; a server it describes is held to the rules the tool lock uses (an absolute command that is not a launcher, an https address with no secret in it); its skills are read by the same strict parser as a skill file. A plugin that is installed, or whose skills are already locked, is refused before anything is written, and a failure part-way undoes the install; `remove` deletes only skills that are still exactly what it installed. A run never reads the plugin lock. Marketplace indexes and fetching are not built (6b). See docs/PLUGINS.md.
