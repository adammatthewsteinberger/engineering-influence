Locked MCP servers are wired into model-backed runs (ADR 0008, slice 4c). A run given `EI_TOOL_LOCK` starts each locked server, refuses to start (`TOOL_LOCK_MISMATCH`) if its files, name, version or tools differ from the lock, and stops every server already started; a changed file's server is never run. Each tool is registered as `<server>__<tool>`, but a stage is offered only the tools the lock grants it, so a registered tool that was not granted is refused even if the model asks. Grants live in a new optional `[server.grants]` table in the lock (no wildcards), edited with `ei tools grant` and `ei tools revoke`; `ei tools list` shows them. A locked tool goes through the same runner as the built-in tools (schema check, size cap, untrusted wrapping, journal), and its journal key includes the hash of the server's tools, so an updated server is asked again instead of replaying old answers. A lock in the working directory is not read unless named. A server is still not sandboxed, nothing has run against a third-party server or a live model, and HTTP servers are not built yet. See docs/TOOL_LOCK.md.
