A run that would spend past its cap now waits for a decision instead of failing. Its next model call is refused before it spends, and the run stops as `awaiting_consent` with the amount the call needs. An open `ei acp` session is asked with a permission request to grant that exact amount or deny it; from the command line, `ei run grant RUN_ID` and `ei run deny RUN_ID` decide any waiting run. A denied run parks and can be continued later with `ei run grant RUN_ID --micro-usd N`. See [INTERACTIONS.md](docs/INTERACTIONS.md#agent-client-protocol).
