The process runner's memory meter no longer depends on `PATH` to find `ps`. It looked `ps` up on the `PATH` of the process being run, so a tool started with a restricted `PATH` crashed the runner with `FileNotFoundError: 'ps'` the first time it lasted past the half-second sampling interval, and a `ps` planted on that `PATH` would have been run in its place. It now runs `ps` from `/bin` or `/usr/bin`, and falls back to `PATH` only when neither has it. This surfaced as three intermittent failures in the visual-QA rasterizer tests, which give a fake `pdftoppm` a `PATH` of its own and failed whenever the machine was busy enough for the fake to outlast one interval.
