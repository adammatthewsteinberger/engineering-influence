Added a read API for book runs. `GET /v1/runs/{run_id}` returns a `RunSummaryV1` (status, current stage, the stage plan, the budget as cap, spent, reserved and remaining micro-dollars, the recorded issues and the names of the artifacts stored so far; the brief's idea is left out) and `GET /v1/runs/{run_id}/artifacts/{name}` returns one artifact byte for byte as `application/octet-stream` with `X-Content-Type-Options: nosniff` and `Cache-Control: no-store`. Both sit behind the same API-key guard as the rest of `/v1`, an unknown run is `RUN_NOT_FOUND` and a missing artifact is `ARTIFACT_NOT_FOUND`, and a name that could never be stored (absolute, `..`, a backslash) gets the same answer as one that was never written, so nothing about the store's layout leaks. `ei run status RUN_ID` prints the same summary as one line of JSON and needs only `EI_DATABASE_URL`. The summary and its budget and issue parts are the new versioned contracts `RunSummaryV1`, `RunBudgetV1` and `RunIssueV1`; the routes are read-only, the API opens its run and artifact stores beside the ledger and closes them with it, and the SDK and MCP server have no run methods yet (M8). The documentation also corrects two stale notes: migrations exist now, but the baseline adopts an old outbox table as it is, so a database created before the `dead_at` column must still be recreated.
