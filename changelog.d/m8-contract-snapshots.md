Every public contract is now frozen by a snapshot test. `tests/contracts/` compares the brief, book-config, run-summary and job-message schemas, the REST OpenAPI document the stack really serves (and the shape of its errors), the whole `ei` command tree (every command, option, choice and default, without help text), the SDK's public methods and signatures, the MCP tools and their arguments, the error codes and issue codes found in the source, and the webhook envelope, catalogue, headers and signature with committed copies in `tests/contracts/snapshots/`; a contract that moves fails a test, and `EI_UPDATE_CONTRACTS=1 uv run pytest tests/contracts` rewrites the snapshot when the move is intended. Prose (docstrings, help text, names generated from handler functions) is left out, so rewording is not a change. The new `docs/COMPATIBILITY.md` says what is promised, what counts as compatible and what as breaking, how to change a contract on purpose, and what is not promised (ACP, the experimental pipeline stages, the files a run writes, Python imports). Two contracts changed to make them freezable: **a book config now carries `schema_version`** (version 1; a config without it is read as version 1, so no existing book changes), and **a webhook delivery is now a versioned envelope**, `{"schema_version": 1, "id", "type", "data"}`, with a new `WebhookEventV1` contract whose catalogue (`pipeline.started`, `phase.completed`, `gate.awaiting`, `pipeline.completed`, each with its payload keys) is tested against what the services really record. Nothing delivers webhooks yet; the envelope is frozen so a receiver written now keeps working. `CliApplication` gains a `parser()` method so the tree can be read.
