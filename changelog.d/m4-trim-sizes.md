A book's config can now set `trim_size` (`6x9`, the default, `5.5x8.5` or `5x8`) and `paper` (`white`, the default, or `cream`); a config that sets neither builds exactly the same files as before, which a before-and-after build of the non-fiction fixture confirmed byte for byte. The trim size sets the interior's page size, the cover layouts and the ebook cover's proportions, and the PDF check now expects the book's own page size instead of a fixed 432 x 648 pt; the paper sets the spine width of the paperback and hardcover wraps (0.002252 in a page for white, 0.0025 for cream). They are two small models, `TrimSize` and `PaperStock`, that replace the constants that were hard-coded in the cover spec and the PDF geometry (`KdpCoverSpec.TRIM_W`, `TRIM_H` and `PAPER_WHITE`, and `KdpGeometry.TRIM`, are gone). The TeX class takes its size from `\finetrimwidth` and `\finetrimheight`, which the generated document sets before the class loads and only for a size other than 6x9. KDP does not print a hardcover at 5x8, so a 5x8 book is paperback and ebook only: it gets no hardcover interior, no hardcover wrap and no hardcover artifact in the inventory, a `formats.hardcover` or `release.formats.kdp_hardcover` is refused, and its pricing no longer needs a hardcover price (one that is given is still checked). The hardcover column follows KDP's published sizes as understood today and should be confirmed against KDP's current list. `BookConfigV1` gains the two settings and the brief's `trim_size` is now one of the three sizes instead of free text. The toolchain test builds three books, adding a 5x8 pocket book and moving the novel to 5.5x8.5 on cream paper, and checks the page sizes and the wrap widths from the real outputs.
