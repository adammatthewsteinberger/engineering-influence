Added `AdvanceRun`, the service that moves a book run one stage at a time and is safe under redelivery, retries and crashes. A delivery names a run, a stage and an attempt: the current stage executes through the new `StageExecutorInterface` port, the run is saved, and the next stage is queued as a `run.advance` job. A message for a stage the run has already passed is skipped, a message for the stage just before the current one means a worker saved the advance and died before queueing the next stage, so the current stage is queued again, and a message for a later stage is refused. Failures are sorted by the new `FailureClassifier` into retry (`TransientStageError`, timeouts and dropped connections, up to a limit, then the run fails with a blocking `retries-exhausted` issue), park (`CapacityExhaustedError` parks the run on the same stage until it is resumed) or stop (anything else fails the run and records the error type and message, cut to 200 characters). The budget's `spent` is recomputed from the run journal after every attempt, so a crash cannot lose the cost of a call that happened and a replayed call is never counted twice. `BookRun` gains `start()`, and the new `AdvanceOutcome` and `StageReport` models describe a delivery's result and what a stage reports. Two deliveries of one stage can overlap, so every change to the run goes through a new `swap` on `RunRepositoryInterface`, which stores a replacement only if the stored run is still exactly what the delivery read (the SQL version is a single conditional `UPDATE` on the stored document, so it needs no new column or migration); the delivery that loses reports `SKIPPED` and neither overwrites the winner nor queues anything, so duplicates cannot compound. If the journal ever records more than the cap, the run fails with a blocking `budget-exceeded` issue instead of raising and being redelivered forever, and `Budget` now raises `BudgetExceededError` for that case too. A crash-injection test drops a save or an enqueue at every point and checks that the run still finishes with every artifact and the exact spend. Nothing runs it yet: wiring it into the worker comes with the model-backed stages.
