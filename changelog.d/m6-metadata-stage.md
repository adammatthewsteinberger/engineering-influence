A non-fiction run now has a `metadata` stage after `outline`. It writes the store listing (title, subtitle, a description of at least 80 words, seven keywords and one to three Amazon categories) in a fixed format that is read strictly, so an unreadable or out-of-contract listing stops the run where it is written (`METADATA_INVALID`). The assemble stage puts it in the book's config, with the release contract's keywords and categories, and a listing made this way passes the release metadata and category checks. The author's own details (author, publisher, edition, bio, and optionally year, website, email, ISBNs, dedication, copyright notes and earlier titles) come from a TOML file named by `EI_AUTHOR_PROFILE`, are written into the config, and are never sent to a model; see CONFIGURATION.md. With a profile, an assembled book has what the build needs. Recorded in ADR 0010.
