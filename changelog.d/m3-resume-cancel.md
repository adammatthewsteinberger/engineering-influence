Added `ResumeRun` and `CancelRun`, and an `ei run` command group to call them (`ei run resume RUN_ID`, `ei run cancel RUN_ID`) against the stack's database. Resuming a parked run moves it to running with a compare-and-swap and only then queues its current stage, because a message that arrives while the run is still parked is skipped; resuming a run that is already running just queues the stage again, so a resume that died between the two steps is repaired by running it once more, and a completed, failed or cancelled run is refused with `RUN_FINISHED`. Cancelling is idempotent, refuses a completed or failed run, and reads the run and swaps again a few times if a worker advances it in the meantime (then `RUN_CHANGED`, marked retryable); a stage already executing is not interrupted, but the worker's own swap then loses to the cancel, so the run stays cancelled and nothing further is queued. The commands print one line, exit 0 on success, 1 when the run cannot do what was asked (unknown, finished or changing) and 2 on setup trouble such as a missing setting, an unreachable broker or a database that was never migrated, never print a traceback, and need the `runtime` extra. `CliRuntime` takes an optional queue so the commands can be driven in tests without a broker.
