A locked MCP server that declares the `resources` capability now offers two tools the client adds itself, `list_resources` and `read_resource`, with fixed descriptions and schemas (not the server's). They are pinned by the tools hash, granted to a stage only by name (`ei tools grant NAME STAGE list_resources read_resource`) and offered to no stage by default; their results are untrusted tool output. `read_resource` takes a one-line uri of at most 2,000 characters and returns text only (binary content is noted as left out); `list_resources` shows at most 200 entries. Nothing is subscribed to. **A server that declares resources and was locked before this change no longer matches its lock**, because its tool list has two more tools: re-lock it with `ei tools add --replace`. A server with its own tool of either name keeps it and gets neither of ours. Run against a small server written for the tests only, not a third-party server.
