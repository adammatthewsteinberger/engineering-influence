Added the run repository and the run journal. Two new ports, `RunRepositoryInterface` (save, get, list ids) and `JournalInterface` (record, find, entries), each have an in-memory implementation for local use and tests and a SQLModel implementation for SQLite and PostgreSQL. A saved run is stored as JSON with its status and stage in their own columns, and loading it rebuilds every model so the models re-check their own rules. The journal keeps the first answer recorded for a run, stage and request and returns it on a repeat, and the database enforces that with a unique constraint, so two workers racing on the same request converge on one answer. Nothing uses them yet; the next slices add the artifact stores, migrations and the `AdvanceRun` service.
