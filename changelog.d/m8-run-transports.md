Book runs can be started from a brief over the API, MCP and the SDK (M8.3): `POST /v1/runs` takes the brief contract v1 and answers `201` with the new run, `create_run` is the MCP tool and the SDK method (sync and async). All of them use the same `CreateRun` service as `ei run create`, and a parity test checks each returns the same run for the same brief. Creating a run now has its plan mapping in one place (`CreateRun` builds it by default), not one per wiring. The command line prints a line of text rather than the run, so it is not in the JSON parity comparison. Nothing here lists, resumes or cancels a run over the API, MCP or SDK yet.
