A locked MCP server that runs on this machine now runs inside a native sandbox. On macOS it runs under `sandbox-exec` with the network denied, writes only in its own working directory, and no reads of the credential directories (`~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.kube`, `~/.config/gcloud`). On Linux it runs under bubblewrap, with a read-only system, one writable directory, and fresh network and process namespaces. Where neither is available, a locked server is refused with `SANDBOX_UNAVAILABLE` and is not started. On macOS, reads outside the credential directories are still allowed, because a server must load its own libraries. The approval a session asks for before a server first starts is a later change.
